## 1. Motivation & Problem

Today in Bitecho, a subnet is an unstructured string named into existence by first use: there is no formal creation act, no canonical hierarchical directory entry, no cryptographic owner set, and no protocol-visible membership object. While `bitecho.core.subnet` enforces constrained policy axes (`:subnet/gate`, `:subnet/economy`, `:subnet/replication`) and `bitecho.memento.circles` models local Rolodex-backed circle descriptors, sociocratic circle governance runs largely as social convention over broadcast subnets.

This creates three structural gaps as Bitecho prepares for seed-stage institutional operation:
1. **Legal-to-Network Blind Spot:** **Bitecho Association** (Swiss *Verein*, Zug) as constitutional steward and **Bitecho, Inc.** (Delaware) as commercial arm, alongside the neutral **Protocol Circle**, exist only in the legal map.
2. **Static Deployment-Config Validator Set:** Streamlet BFT (`bitecho.streamlet.core/committee-validators`) reads its committee (`node1..node3`, `ns1..ns3`; `4-of-6`) from static deployment config (`:validators`), while `:reconfigure-membership` (`state_machine.cljc:1842-1891, 2341, 3389`) relies on a single treasury key rather than a Root Association quorum.
3. **Unanchored Allocations & Flat Naming:** Without an anchored root, a hierarchical network/path directory with sovereign individual roots, persistent SCI multisig vaults, and in-band validator rotation, proving sum-to-genesis conservation and safe institutional delegation remains off-protocol.

BIP-024 closes these gaps while strictly preserving Bitecho's core invariants: **sovereign self-certified identity, zero silent failures, strict cross-network isolation, sociocratic consent, and bounded state discipline**.

## 2. Normative Design

### 2.1 Unified Directory Entity Model (Circles, Subnets & Individuals as Equals)
Every registered entity in Bitecho's Directory — whether a multi-member Circle/Subnet or a single Individual — uses the **exact same** pure descriptor schema (`:bitecho/type :directory/entity-descriptor`), pointer path grammar, ACL engine, and verification pipeline:
- An **individual** is a `1-of-1` owner multisig (`:owner-multisig {:threshold 1 :pubkeys [spki-pk]}`).
- A **circle / subnet** is a `k-of-n` owner multisig (`:owner-multisig {:threshold k :pubkeys [spki-pk-1 ... spki-pk-n]}`), proving possession via `:proof/type :directory-entity` quorum proofs (`threshold >= 1`).

**Canonical Pubkey Encoding (Closes Blocker 2):**
All Ed25519 public keys in BIP-024 descriptors, pointers, vault puzzles, and validator-set committees MUST be serialized as **lowercase 88-character hex X.509 SPKI DER** (`302a300506032b6570032100` + 64-hex raw Ed25519 key) across JVM, Node.js, and Browser runtimes. Any `64`-char raw hex input at a boundary MUST be normalized to 88-char SPKI DER before deduplication, sorting, or `crypto/verify` so no duplicate-signer `k-of-n` bypass is possible between runtimes.

### 2.2 Directory Pointers, Expiry Units, ACL Hardening & Retention Discipline
Every Directory entry is a signed `Pointer` (`bitecho.core.data`) whose `:pointer/target` is the 64-char SHA-256 CID of the latest owner-signed `:directory/entity-descriptor` `Blob` (Canonical Fressian, `"application/fressian"`).

**Normative Fixes to `bitecho.core.data`, `memento/constants.cljc`, HTTP & Browser (Closes Blocker 2):**
1. **Strict Epoch vs. Millisecond Separation (`data.cljc:744-749, 854`):** Directory and validator-set pointers MUST use `:pointer/expires-epoch` (integer Streamlet epoch, compared exclusively against finalized `current-epoch`), never `:pointer/expires` (which remains Unix `now-ms` for short-lived ACME/ephemeral pointers). Comparing an epoch integer against `now-ms` is forbidden.
2. **Fail-Closed `:path-acl` & Anti-Tombstone Protection (`data.cljc:504, 538-556, 750-752`):**
   - `verify-pointer` MUST fail closed (`:missing-path-acl`) whenever `:path-acl` is absent or empty.
   - `"dir/*"` paths MUST reject `:proof/type :self` for both writes and tombstones (`:pointer/target nil`). Every `"dir/*"` update or tombstone MUST carry `:proof/type :directory-entity` with `>= threshold` valid distinct signatures from the **prior** `:owner-multisig` (with `threshold >= 1`, explicitly supporting `1-of-1` individuals), strict `new-seq > old-seq`, AND **incoming-key Proof-of-Possession** (`:incoming-pop-signatures`) for every newly added key on rotation. A compromised Directory Authority can therefore **never** unilaterally tombstone `dir/root` or hijack any entity.
3. **BIP-016 Discipline Alignment (`memento/constants.cljc:225-245`):** Extend `validate-pointer-discipline` to accept `:owner-multisig` (`:pubkeys` non-empty, `1 <= :threshold <= (count :pubkeys)`) alongside legacy `:owner-pubkeys`, and mandate `:storage-accounting` on both `:directory/entity-descriptor` and `:root/validator-set-descriptor`.
4. **Offline Restore Pinning:** Nodes MUST pin the latest verified genesis/checkpoint descriptor snapshot for `"dir/root"` and `"root/validators"` exempt from rolling retention eviction, guaranteeing offline nodes can always verify descriptor hash chains upon restore.
5. **Multi-Segment HTTP Routing & Full-URI Caching:** Update `/directory/v1/*` in `src/bitecho/shell/http.clj` (`L2022` area) and `src/bitecho/full_node_main.cljs` (`L1707` area) to route arbitrary slash-separated paths (`/directory/v1/<network-uri>/<path...>`) with binary `"application/fressian"` support, and key `src/bitecho/light_node/core.cljc` directory caches by canonical full URI (`<network-uri>/<path>`) rather than bare leaf nickname.
6. **Browser Persistence Whitelist (`src/bitecho/shell/browser.cljc:812`):** Add all non-liveness BIP-024 persistence keys (`"entity-descriptors"`, `"vaults"`, `"validator-set-history"`, `"network-genesis-cid"`, `"advisory-twin-pubkeys"`, `"directory-cache-v2"`) to `allowed-persistence-keys` (never persisting derived runtime liveness per `AGENTS.md` Rule 4).

### 2.3 Hierarchical Subdomain + Path Directory, Cross-Network Isolation & Sovereign Roots

#### 2.3.1 Subdomain = Network + Strict Cross-Network Isolation (Closes Blocker 1)

- `devnet.bitecho.org` — Devnet
- `testnet.bitecho.org` — Testnet
- `bitecho.org` — Mainnet (canonical root domain; `"mainnet.bitecho.org"` allowed strictly as `n+1` alias per §7.2)

**Mandatory Security Fix (`src/bitecho/config.cljc:104-123`, `account.cljc:41-69`, `state_machine.cljc:212`):**

- Enable `:strict-network-uri? true` on **ALL** networks (`devnet.bitecho.org`, `testnet.bitecho.org`, `bitecho.org`, and any external root network) — never only on `"mainnet.bitecho.org"`.
- Bind `:network-genesis-cid` alongside `:network-uri` in all BIP-024 signing tuples (entity descriptors, validator-set rotations, SCI vault spends, faucet vouchers).
- Reject legacy `"global"` flat descriptors on all hierarchical `"dir/<path>"` paths.

#### 2.3.2 Path = Hierarchical Subnet / Directory Tree
Paths beneath `<network-subdomain>/` form a rooted directory namespace with uniform primitives for subnets, circles, and individuals:
- `<net>/root` — Root Circle (Bitecho Association)
- `<net>/root/protocol` — Protocol Circle (`<net>/root/protocol/standards` for external root-network seats)
- `<net>/root/inc` — Bitecho, Inc. (`<net>/root/inc/board`, `<net>/root/inc/faucet`)
- `<net>/id/<pubkey-cid>` — Sovereign self-certified individual root
- `<net>/commons/<handle>` — Optional self-registered sovereign handle (first-come, non-org-owned)

#### 2.3.3 Sovereign Individual Roots vs. Revocable Org Seat Leases (Closes Blocker 6)
To eliminate individual vassalage and departure-squatting traps:
- **Sovereign Identity (`<net>/id/<pubkey-cid>`):** Every individual and autonomous agent owns a sovereign `1-of-1` entity rooted at `<net>/id/<sha256(spki-pubkey)>` (and optionally `<net>/commons/<handle>`). No organization (`root`, `protocol`, or `inc`) can revoke, censor, or squat an individual's sovereign root. An individual may delegate child paths under their own sovereign root (e.g., `<net>/id/<pk-cid>/agents/worker-1`).
- **Organizational Seat Leases (`<net>/root/protocol/dev/nexus`, `<net>/root/inc/board/johndoe`):** Paths under an organizational circle are **parent-revocable seat leases** (`:entity-kind :seat-lease`, `:lease-holder-uri "<net>/id/<pk-cid>"`). A lease grants role/namespace authority inside the org while active; if a member departs, the parent circle's `:owner-multisig` can revoke or reassign the org seat lease without affecting the individual's sovereign `<net>/id/<pk-cid>` identity, funds, or Rolodex history, and the departing member cannot hold the org path hostage.

### 2.4 Root Circle = Bitecho Association (Schweizer Verein)
`<network-uri>/root` represents the **Bitecho Association** (Swiss *Verein*, Zug) with strictly **constitutional, non-operational** powers:

4. Constitutional ratification of validator-set rotations (§2.5) and Cold-Root Emergency Recovery.

### 2.5 In-Band Streamlet BFT Validator-Set Rotation, Catchup & Cold-Root Recovery (Closes Blocker 4)
Bitecho maintains **one Streamlet BFT chain per root network**, with the validator committee governed strictly **in-band**:

1. **In-Band Finalized Receipts (Zero Out-of-Band Split-Brain):**
   - Validator committee changes are NOT applied from out-of-band Gossip pointers. They MUST be submitted and finalized as Streamlet BFT `:rotate-validator-set` receipts carrying the Root-multisig-signed `:root/validator-set-descriptor` (and mirrored to the `"root/validators"` Pointer for discovery).
   - The active committee and epoch-indexed committee history MUST be hashed directly into `compute-checkpoint-state-digest` in `src/bitecho/state_machine.cljc`.
   - Single-key `:reconfigure-membership` (`state_machine.cljc:1842-1891, 2341, 3389`) is gated behind Root Association quorum in `n+1` and removed in `> n+2`.
2. **Activation Lead Time & Fast Equivocation Ejection:**
   - Normal rotations require `:epoch-effective >= (max :not-before-epoch (+ epoch-finalized validator-activation-lead-epochs))` (default `lead = 6` finalized epochs on live networks).
   - **Fast Emergency Ejection:** If a finalized receipt includes a cryptographic equivocation proof (two conflicting signed votes/proposals from validator $v$ in the same epoch), a Root quorum may eject $v$ at `epoch-finalized + 1` (provided remaining committee size preserves BFT liveness `>= 4` or `>= 3f + 1`).
3. **Historical Catchup Verification (`src/bitecho/streamlet/core.cljc:732`):**
   - State retains an immutable epoch-indexed map `:validator-set-history {epoch-effective -> {:committee [...] :quorum-threshold q :descriptor-cid cid}}`.
   - `verify-ancestor-quorum` MUST resolve the committee active at each ancestor block's `:epoch` (`(committee-at-epoch history (:epoch block))`) rather than the current head committee, guaranteeing lossless catchup across arbitrary committee rotations.
4. **Anti-Downgrade Rule:** Static `:config :validators` fallback is permitted **strictly iff `last-finalized-epoch == 0`** (genesis bootstrap). Once epoch `>= 1` has finalized, nodes MUST reject any static fallback (preventing eclipse downgrade).
5. **Cold-Root Emergency Recovery Protocol:**
   - Triggered ONLY if Streamlet BFT halts (loss of `>= 1/3` active validator keys so no new block can finalize).
   - A supermajority of offline hardware-backed Root Association keys (`>= root-threshold`) signs a `:cold-root-recovery` bundle specifying `:network-uri`, `:network-genesis-cid`, `:recovery-seq > last-finalized-epoch`, `:last-known-finalized-block-hash`, and the replacement `:committee`.
   - Operators verify the recovery bundle out-of-band, supply its CID via explicit `--cold-root-recovery-cid` startup flag (never auto-accepted over gossip), emit a high-severity `:cold-root-recovery-activated` diagnostic in `/statusz`, and record the recovery bundle permanently in `:validator-set-history`.

#### 2.6.1 Sociocratic Governance Primitives (Beyond Bare `k-of-n`)
1. **Constitutional vs. Operational Threshold Split:**
   - *Operational acts* (routine pointer updates, bounded `:vault-spend-dac` allowances, sub-path lease management) use standard `k-of-n` `:owner-multisig` execution.
   - *Constitutional acts* (charter/values changes, parent-child admission, validator-set ratification, circle dissolution, custody-bucket reallocation) MUST reference a finalized `:consent-round-cid` proving **sociocratic consent**: (a) **double-linking** (at least one signature from the circle's lead link and one from the child/delegate link where applicable), (b) quorum participation across non-twin human/org seats, and (c) **zero unresolved `:paramount-objection`** ballots.
2. **Human-Anchor Sunset (`2027-06-30`):** `:human-anchor` remains a circle-policy convention (never a protocol liveness gate). At `2027-06-30` (configured via `:human-anchor-sunset-epoch`), any circle still referencing a legacy `:human-anchor` automatically transitions to pure sociocratic double-linked consent with zero founder veto.
3. **`dissolve-circle` Lifecycle:** A constitutional consent round by a circle (or its parent upon sustained liveness failure) may execute `:dissolve-circle`, which tombstones the org path, revokes child seat leases, and atomically returns all remaining SCI vault principal to the parent/Root vault preserving `:custody-bucket` provenance (`0` take).
4. **Lost-Key Recovery Policy:** Both `1-of-1` sovereign roots and `k-of-n` circles may optionally configure a `:recovery-policy {:guardians [...] :threshold r :timelock-epochs T}` (`T >= 168`, cancellable by the active owner key(s) during the timelock window).
5. **Grow-Only `:advisory-twin-pubkeys` Registry (`INV-C5`):** Advisory twin public keys are recorded in a **grow-only** root-anchored set `:advisory-twin-pubkeys`. Once a pubkey is registered as an advisory twin, it can **never** be removed or self-flipped to `:advisory-twin? false` to gain real consent or multisig signing authority.

#### 2.6.2 Two-Mode Privacy (`:visibility :public | :shared-encrypted`)
Every `:directory/entity-descriptor` MUST declare `:visibility`:
- **`:public`:** Plaintext Canonical Fressian blob (mandatory for constitutional roots `root`, `root/protocol`, `root/inc`, and `"root/validators"`).
- **`:shared-encrypted`:** For private subcircles and sovereign individuals who do not wish to expose member rosters, allocations, or `:home-set` endpoints via `/artifact/v1/list?prefix=dir/`. The descriptor payload is AEAD-encrypted (`XChaCha20-Poly1305` / `AES-256-GCM`) to the entity's member group key and published at a blinded subpath hash (`dir/<parent-path>/enc/<hmac-subpath>`); only structural verification headers (`:network-uri`, `:version`, `:prev-descriptor-cid`, `:owner-multisig` commitment, `:retention-policy`, `:storage-accounting`) remain visible to relays for BIP-016 and signature verification.

### 2.7 Membership Is by Key and Role, Not by Box
Membership binds canonical 88-char SPKI DER public keys and explicit roles, never physical hosts (`ns1..ns3` serve naming roles under `root` and relay/validator roles under `root/protocol`).
